# 使用与自定义

你不需要先学一套提示词格式。告诉助手：想讲什么、画给谁看、用什么角色、希望是什么样子，再补上一定要出现的文字就可以。

[直接复制提示词](prompt-examples.md)：按你手里的材料选择一个场景，替换人物和样式即可。

## 还没有角色图

从 [第一次设计自己的角色](character-design.md) 开始：选照片、已有角色图或纯文字其中一种方式，填写用途、外形、服装和性格感觉。先确认主形象，再补动作、进入故事制作；指南内有可直接复制的完整模板。

## 换成自己的角色

```text
使用 bela-hand-comic。我想用自己上传的短发女孩和橘猫，画一组整理房间的故事。
女孩穿黄色卫衣，猫没有衣服；人物细节以附件为准。
保留彩铅手绘感，背景用暖白色，竖版 3:4。
先记录我的角色设定，再拆每页内容，做一张关键示例给我看。
```

没有图片时也可以描述角色。先确认一张角色图能帮助后续保持一致。随包角色都可以替换，也可以用场景、物体或图标讲故事。

## 改配色、笔触和排版

```text
沿用上一组的人物，这次做成四张独立卡片。
用粗蜡笔手绘和蓝白配色，每张横版 4:3，文字在左，人物在右。
每张只放一句短句。全部确认后再拼成两列两行，不要重新绘制已完成的图片。
```

手绘是默认样式，不是唯一可用画风。用户可以指定线描、水彩、蜡笔或其他视觉参考；改变画风后要重新确认一张效果，不能保证不同模型画出相同笔触。

## 把概念画成故事

```text
使用 bela-hand-comic，用准备野餐的小故事说明 Agent、Model 和 Skill 的分工。
读者没有技术背景。先理清完整因果关系，指出比喻容易误解的地方。
逻辑通过后拆页，页数按讲清楚所需安排。先让我看逐页内容和一张关键示例，再画其余图片。
```

先讲清角色在做什么，再出现概念标签。生活比喻可以帮助理解，但不能代替技术事实。图里的帐篷可以代表搭帐篷的本领，需要文案说明，不能让读者把物品直接当成 Skill。

## 只改一张图

```text
使用 bela-hand-comic 编辑这张图。
只把画面文字改成“我们一起准备野餐”，保留人物、动作、配色和构图。
先检查有没有图片编辑能力，改好后逐字核对。
```

一次只提出一个明确修改点更容易检查。用户明确要求一起调整多处时，逐项列出并验收。

## 交付前一起看什么

- 角色还是不是同一个：脸、衣服、配饰位置是否符合本次设定。
- 每张图有没有推动内容：前后能否接上，是否有两张重复讲同一件事。
- 文字是否准确：漏字、错字、额外标题和太小的字都要修。
- 比喻是否清楚：箭头和标签会不会让读者误解。
- 排版是否完整：图片顺序、留白和比例是否符合要求，组合时有没有裁掉内容。

完成后保存现行说明和图片。同一幅的修订确认后可按已授权范围替换；不同内容的图片不要因名称相似被清掉。

## 随包文件怎么分工

`SKILL.md` 管执行步骤，`references/style-guide.md` 给默认参考和提示词模板，`assets/` 放角色及风格图片。`agents/openai.yaml` 提供部分客户端使用的展示名称；不是 API 或模型配置。

你可以先在对话里修改本次设定，不必编辑安装目录。只有想做自己的长期版本时，再另存角色参考和规则；记下改动，更新上游 Skill 前先备份自定义内容。
